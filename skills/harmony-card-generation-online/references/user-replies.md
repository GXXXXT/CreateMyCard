# 固定回复与用户可见信息规范

执行前读取一次本文档。所有用户可见回复按编号选择模板，仅替换允许的占位符；不得自由改写、透传工具 message 或拼接内部解释。主流程负责规定发送时点，本文档是 Skill 内话术全文的唯一维护位置。

## 事实说明与任务结果

- 应发送的回复必须实际发送，不能只准备草稿或写入工具入参。遵循宿主回复规则，不从工具职责描述推断用户已收到卡片结果回复。
- R01/R02 必须先于本 Skill 首个固定卡片工具，不受进入 Skill 前已执行 WebSearch 的影响。
- 本轮采用且尚未告知的事实须在生成前用 R16W/R16 直接说明，不描述获取过程；已告知的同一事实不重复发送。
- 生成后根据真实结果选话术：成功 R18C/R18E，部分满足追加 R19，unsupported 用 R07，其它失败用 R14。
  create 反馈生成结果与用途，edit 反馈修改结果与本次调整；不复述搜索数据值，不解释执行过程。
- 应发送的结果回复不能以“已准备好模板”代替。结果已处理且应发送的回复已发送才完成；URL 留存只维护编辑链。

## 占位符与组合规则

- 不输出编号、占位符名称或大括号。只有 R11/R12 的多项授权引导和 R18 + R19 的部分满足允许组合，其它情形每次选择一个对应模板。
- 澄清只选 R03/R04/R05/R09 中一个，询问一个用户可回答的问题并等待；不向用户询问技术字段、设备是否支持或权限状态。
- 缺失内容使用用户原话中可确认的内容，以本轮能力裁决、来源失败或服务移除结果核对；多个名称按原顺序去重，以“、”连接，无法可靠提炼时使用“相关内容”。
- 相近需求为 1～3 条用引号包围、顿号分隔的可复述请求。已有合法概述时从实际候选提炼；尚无概述时只用天气、日程、运动、设备电量或系统状态通用示例，不承诺可用。工具异常使用 R14，不追加推荐。
- R10 描述具体不支持的修改，例如“将天气替换成日历数据”“修改点击动作”，不把所有替换都说成新增。重新创建需求仅供用户下一轮主动发起，不自动执行。
- 授权名称、设置路径只取正常权限返回中的合法明细；同名保留第一项，逐行发送 R11/R12，不追加建议。明细非法使用 R14，不猜测路径。
- 事实说明直接呈现内容，不使用“网络搜索”“获取到”“根据搜索结果”“经校验”或工具调用过程话语；必要的安全信源名称直接附在事实旁，不输出工具标识。来源没有用户显示名不影响真实调用和事实采用。
- 事实摘要只包含已校验、实际用于本轮参数或有效需求且尚未告知的简短事实；保留必要地点、日期、时区、单位和不确定性，不输出未采用内容、推测、原始响应或链接。占位符末尾不带句号，由模板统一补齐。
- Skill 前已有多条 WebSearch 结果在权限阶段后合并采用，对尚未告知的事实发送一次 R16W；每次补查回填后对尚未告知的采用事实立即发 R16W 或 R16。已告知的同一事实不重复发送，没有新增待告知事实时不凑话术；已有结果和新补查均不发送调用前进度。
- 用途、主要用途说明和修改概括只来自本轮有效需求与真实结果。create 简述卡片主要用途，edit 可结合真实编辑链概括本轮实际调整，不复述搜索数据值，不把候选或计划当成已确认的渲染细节。信息有限时作保守概括；部分满足只描述保留用途与真实调整，并追加确定缺失。
- 必要工具失败使用 R14；核心外部来源失败使用 R17；次要来源失败使用 R08C/R08E。权限 invoke 级异常不发送任何异常话术，继续执行后续步骤。

## 发送前检查

1. 不含产物 URL、来源链接、Markdown URL、结果代码块或替代结果标记。
2. 不含能力 ID、schema、provider、TaskSpec、CardSpec、DSL、OBS、IDS、错误码、请求 ID、工具包络、内部草稿或敏感信息。
3. 不透传或润色业务 message；不宣称已添加到桌面、已安装、已开启权限或其它未执行操作。
4. 开始处理不表示成功，事实说明不表示卡片已生成；成功按真实业务结果判断，结果回复不复述搜索数据值或解释执行过程。
5. 调用生成前，核对需要告知的新事实已实际发送；遗漏时先用 R16W/R16 直接说明，已告知的同一事实不重复发送。
6. 结束前，确认工具结果已处理且应发送的结果回复已实际发送；不能以“已决定怎么回复”或工具职责描述代替实际发送。
